# Purpose

This document defines every diagram required throughout the LeadFlow Software Proposal.

The proposal should explain ideas visually wherever possible.

Diagrams should simplify complex concepts rather than decorate the proposal.

Every diagram should be:

- Minimal
- Professional
- Easily understandable
- Consistent
- Fully editable (SVG preferred)

These diagrams should be recreated in Canva or Figma using the LeadFlow Design System.

---

# Diagram Style

All diagrams should follow the same visual language.

Boxes
- White background
- 12pt corner radius (rx="12" for primary, rx="8" for secondary)
- Thin gray border (Slate 200)
- Soft shadow

Connectors
- Straight lines
- Blue (#2563EB)
- 2px thickness
- Arrowheads

Typography
- Poppins for titles
- Inter for labels and descriptions

Spacing
- Generous whitespace.
- Never overlap elements.

# Core Diagrams (6 Layouts)

## Diagram 01: Workflow Comparison
* **Proposal Page:** Page 02, Page 13, Page 15
* **Objective:** Contrast manual, fragmented operations with modern, centralized digital routing.
* **Layout:** Side-by-side vertical comparisons. Red accent boxes and labels representing manual fragmentation on the left, and Blue accent boxes representing LeadFlow's automated process on the right.
* **Caption:** Centralizing operations reduces human error, automates lead tracking, and saves daily manager hours.

---

## Diagram 02: Challenge Grid (3x3 grid)
* **Proposal Page:** Page 03
* **Objective:** Detail the client's 9 primary operational pain points.
* **Layout:** 3x3 layout of cards with thin borders, soft shadows, and monochrome Lucide icons.
* **Caption:** A disconnected process creates severe leaks in recruitment visibility.

---

## Diagram 03: Centralized Database Hub
* **Proposal Page:** Page 04
* **Objective:** Show how LeadFlow acts as the single central hub for all inputs and outputs.
* **Layout:** Central blue node representing "LeadFlow Engine" connected via dashed lines to left-side input files (CSV, Excel) and right-side outputs (Calls, Reports, WhatsApp).
* **Caption:** Streamlining data flows prevents lead duplication and guarantees recruiter accountability.

---

## Diagram 04: Implementation Roadmap
* **Proposal Page:** Page 11
* **Objective:** Chart the 6-stage rollout journey (Discovery, Configuration, Import, Training, Launch, Support).
* **Layout:** Horizontal timeline path with circles containing monochrome icons and connecting lines.
* **Caption:** A structured, low-risk deployment ensures seamless transition within weeks.

---

## Diagram 05: Partnership Lifecycle
* **Proposal Page:** Page 14
* **Objective:** Reassure the client of continuous long-term support and future platform expansion.
* **Layout:** Horizontal 5-stage timeline path (Launch, Onboarding, Monitoring, Support, Growth) indicating support scopes and future API opportunities.
* **Caption:** Post-launch support and future integrations guarantee the platform scales with your business.

---

## Diagram 06: Next Steps Timeline
* **Proposal Page:** Page 16
* **Objective:** Clarify immediate kickoff milestones.
* **Layout:** Horizontal 4-stage timeline path (Approval, Kickoff, Development, Go Live).
* **Caption:** A clear starting path ensures immediate momentum post-approval.

# Diagram Color Rules

* **Main Accents:** LeadFlow Blue (#2563EB)
* **Outcomes / Success:** Green (#10B981)
* **Alerts / Problems:** Red (#EF4444)
* **Backgrounds / Neutrals:** Slate Palette (#F8FAFC, #E2E8F0, #64748B)

---

# Diagram Icon Rules

Only use standard monochrome Lucide icons (e.g. Phone, Database, ShieldCheck, FileSpreadsheet, BarChart3, Bell, ClipboardList).

---

# Diagram Export Requirements

Maintain every diagram as:
* SVG (production code)
* PNG (reference preview)
* PDF (print output)

Every diagram must remain fully editable in source form.

---

# Final Principle

Every diagram should make the proposal easier to understand and reduce text density. If a visual exists only for decoration, remove it.
